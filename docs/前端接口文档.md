# 《覆写：故事新编》前端—后端接口文档

> 英文名：OVERWRITING: ANOTHER CHOICE  
> 文档版本：v1.0  
> 更新时间：2026-08-26  
> 依据：当前 `web/` 前端、PRD v1.1、现有 FastAPI 后端代码  
> 面向：前端开发、后端开发、联调测试

---

## 1. 文档结论

当前前端是一个**离线优先的静态网页**，尚未发出任何 HTTP 请求。用户名、书籍、章节、阅读位置、书签、铭文、读者终章和契名版本均保存在浏览器 `localStorage` 中。

按照 PRD v1.1，初赛不开发账号、服务器存档和多设备同步。因此后端初赛阶段只需要向前端提供：

1. 服务健康检查；
2. AI 助手连接状态；
3. AI 阅读助手统一接口：解释选中文字、总结当前章节、推荐三个问题。

TXT 导入、普通搜索、朗读、翻页、主题、铭文 CRUD、完整度计算和契名仪式继续由前端本地完成。复赛需要云同步时，再实现第 8 章预留的状态同步接口。

## 2. 接口范围与优先级

| 优先级 | 接口 | 状态 | 初赛要求 |
|---|---|---|---|
| P0 | `GET /health` | 后端已存在 | 必须保留 |
| P0 | `GET /api/v1/ai/status` | 需要新增 | 推荐实现 |
| P0 | `POST /api/v1/ai/assist` | 需要新增 | 推荐实现，至少真实支持 `explain` |
| P0.5 | `POST /api/v1/books/import` | 预留适配接口 | 可不做，前端已有离线 TXT 导入 |
| P1 | `GET /api/v1/state/{client_id}` | 预留 | 复赛再做 |
| P1 | `PUT /api/v1/state/{client_id}` | 预留 | 复赛再做 |
| 现有 Agent | `/api/import`、`/api/generate`、`/api/works*` | 后端已存在 | 当前阅读前端不直接调用 |

### 2.1 明确不需要后端的功能

| 功能 | 当前实现位置 | 原因 |
|---|---|---|
| 用户名、主题、字号、行距 | `web/assets/js/store.js` | 本机设置，断网也要可用 |
| 书库和示例书 | `store.js`、`data.js` | 初赛本地数据 |
| TXT 解析和章节切分 | `library.js` | 前端已完成，限制 4MB |
| 翻页、目录、普通搜索 | `reader.js` | 纯本地文本操作 |
| 书签 | `reader.js` | PRD 明确不要求同步 |
| 系统朗读 | 浏览器 `SpeechSynthesis` | 使用本机声音 |
| 铭文创建、编辑、删除 | `reader.js`、`store.js` | 核心流程必须离线可用 |
| 完整度计算 | `store.js` 中 `OW.RULES` | 规则必须保持单一来源 |
| 读者终章和契名 | `finale.js`、`ceremony.js` | 初赛本地真实完成 |
| 动画、法阵和视觉效果 | CSS、SVG、JS | 不涉及业务数据 |

## 3. 通用约定

### 3.1 服务地址

- 开发环境 Base URL：`http://localhost:8000`
- API 版本前缀：新增产品接口统一使用 `/api/v1`
- 前端静态服务常用地址：`http://localhost:8777`、`http://127.0.0.1:8779`

后端开发环境需允许以上前端地址跨域访问。若部署到公网，不应继续使用 `allow_origins=["*"]`，应改为实际前端域名。

### 3.2 数据格式

- 除文件上传外，请求和响应均为 `application/json; charset=utf-8`。
- 文件上传使用 `multipart/form-data`。
- JSON 字段统一使用 `snake_case`，与现有 FastAPI 接口保持一致。
- 章节和段落下标均从 `0` 开始。
- 时间统一使用 Unix 毫秒整数，与前端 `Date.now()` 一致。
- AI 返回内容必须是纯文本或 Markdown 文本，不得返回可直接执行的 HTML。

### 3.3 认证与 API Key

初赛没有账号系统，不使用登录 Token。

推荐由后端从服务器环境变量读取模型 API Key，前端只获取“是否已连接”和模型名。后端不得把真实 API Key 返回给前端、写入日志或包含在错误信息中。

当前前端设置页中的 Key 仍只保存在浏览器本地。初赛联调时不要求后端接收或保存该字段。

### 3.4 成功响应

成功时直接返回业务对象，不再额外包一层 `data`，与现有 FastAPI 风格保持一致。

```json
{
  "connected": true,
  "model": "deepseek-chat"
}
```

### 3.5 失败响应

所有新增接口统一返回：

```json
{
  "detail": "AI 服务暂时没有响应，请稍后重试。",
  "code": "AI_TIMEOUT",
  "retryable": true,
  "request_id": "req_01J6ABCDEF"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `detail` | string | 是 | 可直接给用户看的中文提示 |
| `code` | string | 是 | 稳定错误码，前端据此决定提示方式 |
| `retryable` | boolean | 是 | 是否适合显示“重试”按钮 |
| `request_id` | string | 否 | 后端日志追踪编号，不含敏感信息 |

### 3.6 推荐超时

| 接口 | 前端超时 |
|---|---:|
| 健康检查、AI 状态 | 3 秒 |
| 解释选中文字 | 30 秒 |
| 总结章节、推荐问题 | 45 秒 |
| 现有 `/api/generate` | 不建议由当前页面同步等待；若调用至少 180 秒 |

## 4. 前端核心数据模型

本章用于让后端理解前端数据。P0 AI 接口不需要保存完整对象，复赛同步时才使用。

### 4.1 Book（书籍）

```json
{
  "id": "b-lamp",
  "sample": true,
  "locked": false,
  "title": "第七盏灯",
  "author": "佚名·抄经室辑录",
  "subtitle": "一本等人开口的书",
  "hue": 0,
  "chapters": [],
  "current_chapter": 1,
  "inscriptions": [],
  "bookmarks": [],
  "finale": "",
  "signature": null,
  "first_inscription_done": false,
  "updated_at": 1787716800000
}
```

| API 字段 | 当前前端字段 | 类型 | 说明 |
|---|---|---|---|
| `id` | `id` | string | 书籍唯一编号 |
| `sample` | `sample` | boolean | 是否为内置示例书 |
| `locked` | `locked` | boolean | 是否尚未解封 |
| `title` | `title` | string | 书名 |
| `author` | `author` | string | 原作者，契名时不可覆盖 |
| `subtitle` | `sub` | string | 书卡副标题 |
| `hue` | `hue` | integer | 封面配色编号，当前为 `0~2` |
| `current_chapter` | `page` | integer | 当前章节下标 |
| `finale` | `finale` | string | 读者终章 |
| `signature` | `signed` | object/null | 契名快照 |
| `first_inscription_done` | `firstInsDone` | boolean | 是否已播放第一枚铭文仪式 |

### 4.2 Chapter（章节）

```json
{
  "title": "第二章 · 空白的批注",
  "paragraphs": [
    "第七盏灯下摊着一本无名书。",
    "伊兰试着在压痕旁写下一个字。"
  ]
}
```

前端当前字段 `paras` 在 API 中映射为更明确的 `paragraphs`。

### 4.3 Inscription（铭文）

```json
{
  "id": "ins_01J6ABCDEF",
  "book_id": "b-lamp",
  "chapter_index": 1,
  "paragraph_index": 0,
  "start_offset": 0,
  "end_offset": 9,
  "quote": "纸面干净得反常",
  "kind": "query",
  "body": "真的干净吗？作者在这里没有说实话。",
  "created_at": 1787716800000,
  "updated_at": 1787716800000
}
```

| 字段 | 当前前端字段 | 约束 |
|---|---|---|
| `chapter_index` | `ch` | 从 0 开始 |
| `paragraph_index` | `para` | 从 0 开始，不支持跨段 |
| `start_offset` | `s` | 选区起点，包含该字符 |
| `end_offset` | `e` | 选区终点，不包含该字符，即 `[start, end)` |
| `quote` | `quote` | 必须等于原段落对应切片 |
| `kind` | `kind` | `echo` / `query` / `link` / `cont` |
| `body` | `body` | 用户自己的回应，不得由 AI 自动写入 |

四类含义：

| 枚举 | 中文 | 含义 |
|---|---|---|
| `echo` | 回响 | 感受和共鸣 |
| `query` | 诘问 | 质疑或不同意见 |
| `link` | 星链 | 联结其他书、经历或人物 |
| `cont` | 续章 | 沿着原文继续创作 |

### 4.4 Bookmark（书签）

```json
{
  "chapter_index": 1,
  "paragraph_index": 0,
  "text": "墨落纸上，字迹缓慢散开",
  "created_at": 1787716800000
}
```

初赛版一本书的同一章节最多一个书签，点击书签按钮采用“存在则删除，不存在则新增”的切换行为。

### 4.5 Signature（契名快照）

```json
{
  "reader": "测试者",
  "author": "佚名·抄经室辑录",
  "version_no": 1,
  "signed_at": 1787716800000
}
```

关键规则：`author` 必须从原书复制，后端不得接受前端用空值或其他名字覆盖原作者。

## 5. P0 接口

### 5.1 健康检查

#### `GET /health`

**状态：现有后端已实现。**

前端用途：启动后判断后端是否可访问；失败时只关闭 AI 能力，不阻塞本地阅读。

成功响应：

```json
{
  "status": "ok"
}
```

验收：正常情况下 3 秒内返回 HTTP 200。

---

### 5.2 AI 连接状态

#### `GET /api/v1/ai/status`

**状态：需要后端新增。**

前端用途：设置页显示“已连接 / 未连接”、当前模型和可用能力。即使没有配置模型，也返回 HTTP 200，不将“未配置”当成服务器故障。

成功响应（已配置）：

```json
{
  "connected": true,
  "provider": "deepseek",
  "model": "deepseek-chat",
  "mode": "real",
  "capabilities": ["explain", "summarize", "questions"]
}
```

成功响应（未配置）：

```json
{
  "connected": false,
  "provider": "deepseek",
  "model": null,
  "mode": "unconfigured",
  "capabilities": []
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `connected` | boolean | AI 是否能接收真实请求 |
| `provider` | string/null | 服务提供方，不包含地址或密钥 |
| `model` | string/null | 当前模型名 |
| `mode` | string | `real` / `demo` / `unconfigured` |
| `capabilities` | string[] | 可用动作列表 |

---

### 5.3 AI 阅读助手

#### `POST /api/v1/ai/assist`

**状态：需要后端新增。**

一个接口承载三种动作，避免前后端维护三套几乎相同的错误处理。

#### 请求体

```json
{
  "action": "explain",
  "book": {
    "id": "b-lamp",
    "title": "第七盏灯",
    "author": "佚名·抄经室辑录"
  },
  "location": {
    "chapter_index": 1,
    "chapter_title": "第二章 · 空白的批注",
    "paragraph_index": 0
  },
  "selected_text": "纸面干净得反常",
  "paragraph_text": "第七盏灯下摊着一本无名书。纸面干净得反常，唯有页边留着一道极浅的压痕。",
  "chapter_text": null,
  "model": null
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `action` | string | 是 | `explain` / `summarize` / `questions` |
| `book.id` | string | 是 | 前端书籍编号，只作上下文和日志关联 |
| `book.title` | string | 是 | 书名 |
| `book.author` | string | 是 | 原作者 |
| `location.chapter_index` | integer | 是 | 当前章节下标 |
| `location.chapter_title` | string | 是 | 当前章节名 |
| `location.paragraph_index` | integer/null | 按动作 | `explain` 必填，另外两类可为 `null` |
| `selected_text` | string/null | 按动作 | `explain` 必填，1~1000 字符 |
| `paragraph_text` | string/null | 按动作 | `explain` 必填，最多 6000 字符 |
| `chapter_text` | string/null | 按动作 | `summarize`、`questions` 必填，最多 20000 字符 |
| `model` | string/null | 否 | 为 `null` 时使用后端默认模型 |

后端应忽略请求中多余字段，不应因为 `action=explain` 同时带了 `chapter_text` 而失败。

#### 动作一：解释选中的原文

请求关键字段：

```json
{
  "action": "explain",
  "selected_text": "纸面干净得反常",
  "paragraph_text": "……完整段落……"
}
```

成功响应：

```json
{
  "action": "explain",
  "text": "这句话通过‘干净’与‘反常’的矛盾，暗示书页曾经承载过内容，只是痕迹被某种力量抹去。",
  "questions": [],
  "is_demo": false,
  "provider": "deepseek",
  "model": "deepseek-chat",
  "request_id": "req_01J6ABCDEF"
}
```

#### 动作二：总结当前章节

成功响应：

```json
{
  "action": "summarize",
  "text": "伊兰发现无名书会读取写在页边的文字，并逐渐意识到那些压痕其实是历代读者留下的回应。",
  "questions": [],
  "is_demo": false,
  "provider": "deepseek",
  "model": "deepseek-chat",
  "request_id": "req_01J6ABCDEG"
}
```

#### 动作三：推荐三个问题

成功响应：

```json
{
  "action": "questions",
  "text": null,
  "questions": [
    "书页为什么会抹去读者写下的内容？",
    "伊兰是在什么时候开始把自己视为共同创作者的？",
    "如果回应最终会消失，写下回应还有什么意义？"
  ],
  "is_demo": false,
  "provider": "deepseek",
  "model": "deepseek-chat",
  "request_id": "req_01J6ABCDEH"
}
```

`questions` 必须正好返回 3 条，每条建议不超过 80 个汉字。

#### AI 接口业务规则

1. AI 结果只用于展示，不自动保存为铭文。
2. AI 调用成功不增加契印完整度。
3. `is_demo=true` 时前端必须显示“演示结果”。
4. 后端不得返回 `<script>` 等可执行 HTML。
5. 用户关闭 AI 面板后，阅读、铭文和契名流程仍可继续。
6. 相同请求可以重试；后端不得因重试自动创建任何业务数据。

## 6. P0.5：可选 TXT 导入适配接口

#### `POST /api/v1/books/import`

**状态：预留；初赛可以不实现。**

当前前端已经在浏览器中完成 TXT 读取、章节识别和本地保存。只有需要让后端共同使用原文时，才调用该接口。

请求：`multipart/form-data`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `file` | file | 是 | 仅 `.txt`，UTF-8/GBK 可由后端探测 |
| `title` | string | 否 | 缺省时使用文件名 |
| `author` | string | 否 | 缺省为“导入·佚名” |

产品限制：文件非空，大小不超过 4MB，不支持 Markdown、EPUB 或 PDF。

成功响应：

```json
{
  "book_id": "book_01J6ABCDEF",
  "title": "导入的故事",
  "author": "导入·佚名",
  "chapter_count": 3,
  "chapters": [
    {
      "title": "第一章",
      "paragraphs": ["……", "……"]
    }
  ]
}
```

如果后端暂不实现此接口，前端继续使用现有 `FileReader` 本地导入，不影响核心功能。

## 7. 现有文学分析 Agent 接口的关系

现有后端已经提供以下接口：

| 接口 | 现状 | 当前前端是否调用 |
|---|---|---|
| `POST /api/import` | 上传 `.txt` / `.md`，上限 10MB | 否 |
| `POST /api/generate` | 同步执行文学分析流水线 | 否 |
| `GET /api/works` | 返回分析作品列表 | 否 |
| `GET /api/works/{work_id}` | 返回分析产物文件内容 | 否 |

这些接口输出的是“剧本摘要、人物信息、世界书”，而当前产品页面需要的是“AI 解释、章节总结、推荐问题”，因此不能直接把 `/api/generate` 的响应塞进阅读助手。

推荐后端复用现有 LLM 配置和调用能力，在其上新增 `/api/v1/ai/status` 与 `/api/v1/ai/assist` 这一层轻量适配，而不是让前端解析 `outputs` 中的文件路径。

### 7.1 当前不一致点

| 项目 | 当前前端 | 现有后端 | 统一建议 |
|---|---|---|---|
| 文件类型 | 只接受 TXT | 接受 TXT、Markdown | 产品接口只接受 TXT |
| 文件上限 | 4MB | 10MB | 产品接口按 4MB |
| 章节结构 | `{title, paras[]}` | 原文件 + 分析产物 | 适配为 `{title, paragraphs[]}` |
| 生成方式 | 页面请求应尽快返回 | `/api/generate` 可能数分钟 | AI 助手使用短请求；长任务以后改异步任务 |
| 文件路径 | 前端不需要服务器路径 | 返回 `saved_path`、`work_dir` | 公网部署时不要暴露绝对路径 |
| CORS | 本地 8777/8779 | 当前允许 `*` | 开发可用，部署后收紧 |

## 8. P1：复赛云同步预留

本章只用于预留字段，初赛后端不要主动开发。

由于当前前端的 `OW.Store` 已经把全部用户状态集中在一个对象中，复赛最小同步方案可以先采用“整包状态同步”，不必立刻拆成十几个 CRUD 接口。

### 8.1 获取状态

#### `GET /api/v1/state/{client_id}`

成功响应：

```json
{
  "client_id": "client_01J6ABCDEF",
  "revision": 7,
  "updated_at": 1787716800000,
  "state": {
    "first_run": false,
    "reader": "测试者",
    "theme": "night",
    "font_size": 18,
    "line_height": 2,
    "version_counter": 1,
    "books": []
  }
}
```

### 8.2 覆盖保存状态

#### `PUT /api/v1/state/{client_id}`

请求：

```json
{
  "base_revision": 7,
  "state": {
    "first_run": false,
    "reader": "测试者",
    "theme": "night",
    "font_size": 18,
    "line_height": 2,
    "version_counter": 1,
    "books": []
  }
}
```

成功响应返回新的 `revision`。当 `base_revision` 已过期时返回 HTTP 409 和 `REVISION_CONFLICT`，避免两台设备互相覆盖数据。

演示模式数据不得上传到普通状态。未来可使用独立 `client_id` 或请求头 `X-Demo-Mode: 1` 隔离。

## 9. 错误码

| HTTP | `code` | 场景 | 前端处理 |
|---:|---|---|---|
| 400 | `INVALID_ACTION` | AI 动作不在枚举中 | 提示版本不兼容，不重试 |
| 400 | `INVALID_FILE_TYPE` | 上传的不是 TXT | 展示文件类型提示 |
| 400 | `FILE_EMPTY` | 文件为空 | 展示文件为空 |
| 404 | `BOOK_NOT_FOUND` | 书籍或作品不存在 | 返回书库并刷新 |
| 409 | `REVISION_CONFLICT` | 云同步版本冲突 | P1 显示冲突处理 |
| 413 | `FILE_TOO_LARGE` | 文件超过 4MB | 提示文件过大 |
| 422 | `VALIDATION_ERROR` | 字段缺失、下标非法 | 展示通用参数错误 |
| 429 | `AI_RATE_LIMITED` | 模型调用频率过高 | 允许稍后重试 |
| 500 | `INTERNAL_ERROR` | 未知后端错误 | 不阻塞阅读，记录 `request_id` |
| 502 | `AI_UPSTREAM_ERROR` | 上游模型报错 | 显示“AI 暂不可用”，允许重试 |
| 503 | `AI_NOT_CONFIGURED` | 后端未配置模型 Key | 显示“魔法助手尚未连接” |
| 504 | `AI_TIMEOUT` | 模型调用超时 | 允许重试或关闭面板 |

## 10. 前端调用时机

```text
网页启动
  ├─ 本地读取 OW.Store（核心页面立即可用）
  ├─ GET /health（后台检查，不阻塞开场）
  └─ GET /api/v1/ai/status（更新设置页的 AI 状态）

用户进入阅读器
  ├─ 阅读、翻页、书签、铭文 → 全部本地执行
  ├─ 点击“解释选中的原文” → POST /api/v1/ai/assist action=explain
  ├─ 点击“总结当前章节” → POST /api/v1/ai/assist action=summarize
  └─ 点击“推荐三个问题” → POST /api/v1/ai/assist action=questions

AI 请求失败
  └─ 只关闭或重试 AI 卡片；不得中断阅读、铭文、终章和契名
```

## 11. 后端联调验收清单

- [ ] `GET /health` 在 3 秒内返回。
- [ ] 未配置 AI 时，`GET /api/v1/ai/status` 返回 HTTP 200 和 `connected=false`。
- [ ] `explain` 能根据选中文本和完整段落返回解释。
- [ ] `summarize` 返回一段可直接展示的章节总结。
- [ ] `questions` 正好返回 3 个问题。
- [ ] AI 返回值不包含可执行 HTML。
- [ ] AI 失败时返回稳定 `code`、中文 `detail` 和 `retryable`。
- [ ] 后端日志和响应中不出现真实 API Key。
- [ ] 前端关闭后端服务后，书库、阅读器、铭文和契名仍可使用。
- [ ] 产品接口不暴露 `saved_path`、`work_dir` 等服务器绝对路径。
- [ ] 初赛不实现账号、云同步和社区接口。

## 12. 前端后续接入建议

正式接后端时，建议新增一个独立文件：

```text
web/assets/js/api.js
```

所有 `fetch`、超时、错误码转换和演示结果都集中在 `OW.Api` 中。页面只调用 `OW.Api.aiAssist(...)`，不要在 `reader.js`、`library.js` 等多个页面里分别手写请求。这样更换后端地址或错误格式时，只需要改一个文件。

本文件仅定义接口契约，目前没有修改前端为联网版本。
