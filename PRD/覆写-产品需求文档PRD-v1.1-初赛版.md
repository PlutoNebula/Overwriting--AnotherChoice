## 0. 初赛策略与范围边界

### 0.1 本阶段的目标

初赛阶段的目标不是完成一款功能齐全的阅读软件，而是在五个有效开发日内，拿出一条**真实、稳定、好看、能录视频的核心体验**：

> 执笔进入 → 选择一本书 → 阅读原文 → 留下四类魔痕 → 形成个人契印 → 写下读者结章 → 名字进入封面。

评审需要在三分钟左右理解三件事：

1. 这是一款读书批注产品，不是普通电子书阅读器。
2. 产品的核心关系是"我与作者"，原作不会被替换，读者通过魔痕回应作者。
3. 最终奖励是读者的名字进入封面，得到属于自己的"覆写版本"。

### 0.2 三层实现方式

为了保证按时交付，所有功能分为三层：

| 层级 | 含义 | 初赛处理方式 |
|---|---|---|
| A：真实可操作 | 视频核心路径和评审可能亲手点击的功能 | 必须真实实现并保存数据 |
| B：预设演示 | 能表现产品想法，但现在接入真实能力成本高 | 可用预置数据、高保真界面或演示模式展示，并明确标注为"演示" |
| C：复赛规划 | 不影响初赛核心故事的完整功能 | 只写进未来规划，初赛不开发 |

### 0.3 演示真实性原则

- 可以使用预设结果展示 AI、推荐等高成本功能。
- 可以使用隐藏的演示模式快速补全魔痕与发布条件。
- 不得把只有静态界面的功能描述成已经真正实现。
- 提交说明中统一使用"初赛范围""预设演示结果""复赛将接入真实服务"等准确说法。
- 视频优先展示真实核心流程，预设演示只用于辅助功能和节省录制时间。

### 0.4 时间路线

| 日期 | 目标 |

| 8月26日晚 | 跑通完整核心闭环 |

## 1. 产品定义

### 1.1 一句话介绍

《覆写：故事新编》是一款西幻风沉浸式读书批注产品，读者通过回响、诘问、暗链和续章参与原作，最终生成署有原作者与自己名字的个人版本。

### 1.2 核心命题

传统阅读软件让批注发生在书页边缘，《覆写》让每一次思考都成为读者版本的一部分。

产品不是让 AI 替用户批改写作，也不是让读者取代作者，而是把阅读变成一场跨越书页的对话：

> **创作仍在，你的选择正在发生。**

### 1.3 核心关系与最终奖励

- 核心关系：**我与作者**。
- 用户行为：阅读原文，并留下自己的判断、经历和创作。
- 最终奖励：**用户名字进入封面**。
- 推荐封面署名格式：

> 原作者 著 · 用户名 缘注
> 第 001 号覆写版本

这样既保留"名字与作者并列出现在封面"的成就感，也不会把读者误称为原作作者。

### 1.4 目标用户

- 喜欢在阅读中画线、批注、写感想的读者。
- 希望与作品建立个人联系的文学爱好者。
- 喜欢仪式感、收集感和西方奇幻视觉的年轻用户。

### 1.5 与参考作品的边界

参考作品为《浮生客栈》。本项目只借鉴"阅读→批注→成长→署名"的产品模式，不复制其代码、素材、文案、计算公式和中式客栈视觉。

《覆写》的差异化方向：

- 世界观：西方奇幻秘籍与隐秘学院，而非客栈、水墨和汉风。
- 交互隐喻：羽毛笔、魔痕、契印、秘籍与契名仪式。
- 产品表达：强调"读者对作者作出另一种选择与回应"。
- 个人成果：不仅显示批注数量，还生成契印、读者结章和个人封面。

## 2. 统一产品术语

初赛开发前必须统一用词，不再在界面中混用"魔印、私藏、秘辛、共鸣、延链"等旧名称。

| 统一名称 | 含义 | 首次出现时的通俗说明 |
|---|---|---|
| 秘籍书库 | 首页书架 | 你的藏书与个人版本所在地 |
| 魔痕 | 所有读书批注的总称 | 你留在原文的回应 |
| 回响 | 记录触动与共鸣 | "这句话让我想到……" |
| 诘问 | 提出质疑或不同意见 | "我并不完全同意……" |
| 暗链 | 联结其他书、现实经历或人物 | "它与另一件事相连……" |
| 续章 | 沿着原文继续创作 | "如果故事继续……" |
| 第一道魔痕 | 每本书第一次批注的仪式 | 你的个人版本从这里开始 |
| 契印 | 由四类魔痕分区点亮的个人图形 | 你的阅读与思考的印记 |
| 读者结章 | 发布前的读后总结 | 读完后写给这本书和作者的话 |
| 契名仪式 | 名字进入封面的发布动画 | 生成你的覆写版本 |
| 个人秘籍 | 已完成契名的个人版本 | 封面同时含原作者和用户署名 |

术语可以有西幻感，但界面中必须同时给出普通人一眼能懂的解释，不能让评审先学习一套世界观才能使用产品。

## 3. 核心用户流程

```text
开场动画（点击羽毛笔"执笔进入"）
        ↓
设置署名（第一次进入时填写用户名）
        ↓
秘籍书库（选择示例书或导入 TXT）
        ↓
阅读器（目录、翻页、搜索、书签、朗读、主题）
        ↓
选中一句或一小段原文，创建四类魔痕
        ↓
第一道魔痕仪式 + 契印逐步点亮
        ↓
四类魔痕各完成一条，填写读者结章
        ↓
契名仪式：名字进入封面
        ↓
个人秘籍回到书库，可再次打开查看
```

### 3.1 初赛发布条件

发布条件采用简单、透明、适合演示的固定规则：

| 条件 | 完整度 |
|---|---:|
| 至少 1 条回响 | 20% |
| 至少 1 条诘问 | 20% |
| 至少 1 条暗链 | 20% |
| 至少 1 条续章 | 20% |
| 读者结章不少于 50 字 | 20% |
| 合计达到 | 100% |

- 阅读进度单独展示，不计入契名条件，避免为了录视频而假装读完整本书。
- 数量超过 1 条可以增强契印亮度，但不继续增加完整度。
- 规则必须集中配置，复赛时可以调整，不要把逻辑散落在多个页面。

### 3.2 用户名规则

- 用户第一次进入书库前填写用于封面署名的名字。
- 用户可在设置中修改名字。
- 发布前必须再次确认署名。
- 发布完成后，该版本保存当时的名字快照，以后修改用户名，不改变已发布版本的署名。

## 5. A 层：初赛必须真实实现的功能

### 5.1 西幻开场动画

#### 体验要求

1. 初始画面是深蓝黑与暮紫色背景，中间有大面积区域呈现羊皮纸质感。
2. 画面右下方放置一支带装饰感的羽毛笔与笔架，显示"执笔进入"。
3. 用户点击羽毛笔后，羽毛笔漂浮并移动。
4. 羽毛笔绘制暮金、暮紫、蓝绿色与少量暮红的魔法线条。
5. 线条**直接勾勒出一本已经打开的双页魔法书**：先勾中间书脊，再勾左右书页轮廓，最后补齐页角、符文和装饰。
6. 不出现合上的书，不从画面上方升起一本书，也不播放"书本打开"动画。
7. 镜头推进时，羊皮纸、皮革、金属包角和符文细节逐渐实体化。
8. 打开的书页自然变成秘籍书库页面，不使用突兀的黑屏或硬切。

#### 操作与性能

- 总时长 6~8 秒。
- 支持点击、Enter 开始；Esc 或"跳过"随时结束。
- 支持 `?autoplay=1`，方便录屏自动播放。
- 书库中有"重播开场"入口。
- 遵从系统"减少动态效果"设置。
- 同时运动的粒子不超过 40 个。
- 适配 1920×1080 与 1366×768。

#### 验收

- [ ] 点击一次只触发一次，不会因连点重复播放。
- [ ] 魔法线条直接形成打开的双页书，没有"合书再打开"。
- [ ] 动画结束稳定进入书库，无白屏、闪烁或明显卡顿。
- [ ] 跳过、重播和自动播放均可使用。

### 5.2 秘籍书库

#### 真实功能

- 展示 3 本示例书：1 本完整可阅读，2 本显示"尚未解封"。
- 书卡展示封面、书名、作者、阅读进度和版本状态。
- 支持导入 TXT 文件，识别"第 X 章"等常见标题，识别失败则作为单章导入。
- 支持继续最近一次阅读。
- 支持删除用户导入的书，删除前二次确认。
- 支持恢复缺失的示例藏书。
- 支持单独重置某本示例书的演示进度��

#### 两种恢复操作必须分开

1. **恢复示例藏书**：只把被移除或缺失的内置书重新加入书库，不影响阅读进度、魔痕和个人版本。
2. **重置示例书进度**：清除该示例书的进度、书签、魔痕、契印、结章和个人版本，必须二次确认。

#### 初赛简化

- 只保证 TXT，不做 Markdown、EPUB 和 PDF。
- 只要求一套稳定的章节识别，不追求兼容所有小说格式。
- 示例书正文使用公版作品或团队原创短篇，避免版权风险。

#### 验收

- [ ] 1 本示例书可完整进入，另外 2 本点击后显示友好提示。
- [ ] 正常 TXT 可以导入并出现在书库。
- [ ] 空文件、非文本文件和过大文件不会导致页面崩溃。
- [ ] 恢复示例藏书不会清空任何进度。
- [ ] 重置进度有明确提示和二次确认。

### 5.3 阅读器

#### 真实功能

- 章节目录与章节跳转。
- 上一页、下一页与键盘左右键翻页。
- 简单关键词搜索，结果可跳转。
- 简单书签：添加当前位置、查看、跳转、删除。
- 朗读：调用浏览器或系统自带的文字朗读能力。
- 朗读至少支持开始、暂停、继续、停止，并可从当前段落开始。
- 字号、行距与阅读底色设置。
- 全局昼间模式与阅读器深色底色使用同一套主题状态，避免出现局部漏色。
- 自动保存阅读位置，刷新后恢复。

#### 初赛简化

- 只做"上一页/下一页"的稳定切换，不做真实纸张翻卷特效。
- 搜索只做普通文字匹配，不做语义检索。
- 书签不要求备注、分类和同步。
- 朗读使用系统声音，不做声音市场、情绪音色或云端配音。

#### 验收

- [ ] 目录、翻页、搜索、书签都能完成一次真实操作。
- [ ] 关闭页面后打开，阅读位置和书签仍在。
- [ ] 朗读可开始、暂停和停止，不支持时给出明确提示。
- [ ] 昼间、夜间切换后没有明显颜色冲突。

### 5.4 魔痕系统

#### 真实功能

- 用户选中一句或一小段原文后打开魔痕面板。
- 可选择回响、诘问、暗链、续章四种类型。
- 保存后，原文显示与类型对应的颜色标记。
- 点击标记可查看、编辑和删除魔痕。
- 保存原文摘录、魔痕内容、类型、书籍、章节和位置。
- 刷新后魔痕仍能还原。

#### 初赛简化

- 优先稳定支持单段内选区，跨多个段落时可提示"初赛版暂不支持跨段批注"。
- 不要求保存后 5 秒撤销。
- 不做复杂的重叠批注，同一段存在标记时，可以提示用户重新选择。
- 不要求 50 条魔痕的压力测试，演示路径稳定即可。

#### 验收

- [ ] 四类魔痕都可各创建 1 条。
- [ ] 四类标记肉眼可区分，且正文仍然清晰。
- [ ] 魔痕可查看、编辑、删除，刷新后不丢失。
- [ ] 不支持的选区会给出提示，不会崩溃。

### 5.5 第一道魔痕、契印、读者结章与契名仪式

#### 第一道魔痕

- 每本书第一次保存魔痕时触发一次 2 秒左右的轻量仪式。
- 提示文案："第一道魔痕已经落下，你的版本从这里开始。"
- 每本书只触发一次，刷新后不重复。

#### 契印与完整度

- 契印由四个可辨认区域构成，对应四类魔痕。
- 某类第一次保存后，对应区域点亮。
- 完整度按第 3.1 节规则显示。
- 初赛只需要一套固定契印，不做真正的生成式个性图案。

#### 读者结章

- 用户可写不少于 50 字的读后总结。
- 未完成四类魔痕或结章不足 50 字时，发布按钮置灰并说明还缺什么。

#### 契名仪式

- 发布前再次确认用户名。
- 动画顺序：封面浮现 → 原作者署名出现 → 用户名以金色书写 → 版本编号生成 → 契印落在封面。
- 推荐封面格式：`原作者 著 · 用户名 缘注｜第 001 号覆写版本`。
- 发布后回到书库，封面持续保留署名和版本编号。

#### 验收

- [ ] 第一道魔痕仪式每本书只出现一次。
- [ ] 四类魔痕分别点亮契印四个区域。
- [ ] 发布条件和缺少项清楚可见。
- [ ] 发布后名字进入封面，刷新后仍然存在。
- [ ] 原作者名字始终保留，不能被用户覆盖或删除。

### 5.6 基础设置与本地数据

- 保存用户名、���籍、章节、阅读位置、书签、魔痕、契印、结章和个人版本。
- 用户数据默认只保存在本机。
- 所有删除和重置操作二次确认。
- 除 AI 外，断网时核心流程仍可使用。
- 不开发账号、服务器和云同步。

## 6. B 层：允许使用预设结果演示的功能

### 6.1 AI 阅读助手

初赛需要拿出可理解的 AI 助手入口和设置界面，但不把真实、多模型、稳定联网接入作为核心验收条件。

#### 初赛界面

- AI 设置：API 地址、API Key、模型名、测试连接、清除配置。
- AI 助手提供三个入口：
  1. 解释选中的原文；
  2. 总结当前章节；
  3. 推荐三个可继续思考的问题。

#### 初赛实现��式

- 优先真实接通"解释选中的原文"一个功能。
- 如果时间或网络不允许，可为指定示例书和指定段落返回预设结果。
- 预设结果必须显示"演示结果"或在提交说明中明确说明。
- 章节总结和问题推荐可以只做高保真演示，不列入真实 P0 验收。
- AI 结果只能辅助用户，不能自动成为魔痕，也不增加完整度。
- 任何真实 API Key 都不能写进代码、仓库、安装包或录屏画面。

### 6.2 演示模式

提供隐藏入口（例如 `?demo=1`），只用于团队录屏和评审演示：

- 可将指定示例书设置为"四类魔痕已各完成一条"。
- 可预填一段超过 50 字的读者结章，但最终点击发布仍由演示者完成。
- 可恢复到首次使用状态，方便重复录制。
- 演示数据与普通用户数据分开，避免污染正常体验。

### 6.3 视频中的高保真画面

以下内容可以用预置样例展示，不要求初赛成为通用功能：

- 更复杂的个人契印变化。
- 精美的 AI 总结卡片与问题推荐。
- 导出个人封面和分享卡片。
- 多本书的已完成个人版本。

视频与 PPT 应把这些描述为"目标体验"或"复赛能力"，不能写成初赛已经全面实现。

## 7. C 层：复赛再实现的功能

## 8. 关键状态与错误处理

| 场景 | 用户看到的结果 |
|---|---|
| 没有用户导入书 | 仍显示 3 本示例书和导入引导 |
| 示例书未开放 | "这本秘籍尚未解封，先从可阅读的秘籍开始。" |
| 没有魔痕 | "这本书还在等待你的第一道魔痕。" |
| 搜索无结果 | "秘籍中未寻得此语。" |
| TXT 无法解析 | 说明文件为空、过大或格式不支持，不出现白屏 |
| 朗读不受当前环境支持 | "当前浏览器无法唤醒朗读，请使用最新版浏览器。" |
| AI 未配置 | "魔法助手尚未连接，核心阅读与魔痕不受影响。" |
| AI 请求失败 | 可关闭、重试，不阻塞阅读 |
| 发布条件不足 | 逐项列出还缺哪类魔痕或多少结章字数 |
| 删除或重置 | 二次确认，默认按钮为取消 |

## 10. 技术方向与简化原则

> 本节只用于约束 Claude Code，不代表现在必须安装依赖或开始写代码。

### 10.1 推荐技术方向

- 网页界面：Vite + React + TypeScript。
- 动画：Framer Motion + SVG + CSS。
- 本地数据：IndexedDB，可使用 Dexie 简化读写。
- 初赛交付：优先保证网页版，Electron 打包为可选加分项。

通俗解释：产品先作为网页完成，最容易调界面和录视频；Electron 只是最后把网页包进 Windows 程序外壳。不能为了 EXE 而误伤核心演示。

### 10.2 明确简化

- 不做后端服务器，不做登录注册。
- 不追求商业级异常覆盖和海量数据性能。
- 不引入复杂通用组件库，优先保证演示路径稳定。
- 不使用 Three.js 等 3D 引擎。
- 不把密钥写死在项目中。
- 开场动画、核心页面与数据模块分开，避免一个文件承担全部逻辑。

### 10.3 数据落地要求

至少保存：

- 用户名和已发布版本的署名快照；
- 示例书与用户导入书；
- 章节和阅读位置；
- 书签；
- 四类魔痕及其原文摘录；
- 第一道魔痕是否出现；
- 契印、完整度、结章、版本编号和个人封面状态。
